# 디자인 시안 관리

## 경로와 열기

- 누구나 읽는 공개 저장소: https://github.com/SimpleorNothing/BloomBreak-design
- 기준 시안: [bloombreak-menu-v12.html](prototypes/bloombreak-menu-v12.html) (파일 내부 버전 v12.2).
- GitHub 파일 화면에서는 HTML이 실행되지 않는다. 저장소의 **Code → Download ZIP**으로 받은 뒤 압축을 풀고 HTML을 브라우저로 연다. 이미지·시작 GIF·수정이력은 파일에 내장되어 별도 서버 없이 작동한다.
- 공개 저장소의 같은 경로 `design/prototypes/bloombreak-menu-v12.html`과 앱 저장소의 이 파일은 같은 내용으로 유지한다. 앱 저장소는 비공개이므로 외부 참조는 공개 저장소 링크를 사용한다.
- 파일명 v12는 시안 계열이다. 작은 변경은 파일 내부 버전을 올리고 Git 변경 내역으로 보존한다. 큰 개편은 새 계열 파일을 만들고 이 문서에서 최신 기준본을 갱신한다.

## 변경·구현 기준

1. APK UI 구현은 기본적으로 최신 승인된 디자인 시안의 메뉴 모양·배치·문구·동작을 따른다. 최신 명시적 사용자 지시가 우선한다. 시안에 없는 기능·과금·권한·저장 정책은 별도 명세를 따른다.
2. 시안의 특정 내용을 바꾸라는 명시적 요청이 있으면 같은 작업에서 시안 HTML도 수정하고 파일 내부 버전을 올리며 수정이력을 추가한다. 구현 과정에서 임의로 시안 기준을 바꾸지 않는다.
3. 단순 구현 수정은 시안을 재설계하지 않는다. 승인된 디자인 변경을 APK에 반영할 때 웹과 Android 자산을 함께 맞추고 동일 PR에 구현·시안·가이드·APK 반영 상태를 기록한다.
4. 각 변경은 HTML의 `#design-history`에 최신순으로 남긴다. 필수 항목은 버전, 한국 기준 날짜, 해당 메뉴/요소, 모양·배치·문구·동작의 변경 전후, APK 반영 상태다. 문구 수정은 실제 이전/새 문구를 적는다. 기존 행을 삭제하거나 과거 이력을 추정해 만들지 않는다.
5. APK 반영 상태는 미반영/미확인/반영 확인으로 구분한다. 반영 확인에는 버전·build 번호·PR/커밋·검증 근거를 연결한다. HTML 등록이나 PR 머지만으로 APK 반영 완료라고 쓰지 않는다.
6. HTML을 열면 수정이력이 기본으로 펼쳐져 있어야 한다. 외부 스크립트 없이 이력을 볼 수 있고 사용자가 접을 수 있게 한다. 이 관리 UI는 APK 제품 화면에 포함하지 않는다.
7. 앱 저장소 PR 검증·머지 후 공개 저장소에 시안·이 관리 가이드를 동기화하고 두 파일의 해시를 확인한다. 공개 저장소에는 앱 코드, 사용자 데이터, 인증정보, 비공개 문서를 올리지 않는다.
